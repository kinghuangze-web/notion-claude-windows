# V2 方案与完成边界

日期：2026-10-19。目标是保留官方 Claude Code 框架、默认提示词与 Skills，将 Notion Opus 5.5 作为后端，并解决按推理轮次创建聊天的问题。不切换模型供应商，不把 Notion 改成仅供 MCP 查询的知识库。

## 问题与实现

| 问题 | 实现 | 验证要求 |
|---|---|---|
| 每轮新建聊天 | 持久化 CC 会话到 Notion 线程的绑定，增量续写 | 同一真实会话多轮只有一次创建 |
| 请求重试与断线恢复 | 事件 ID、待处理基线、历史哈希、串行会话锁、原子存盘 | 未知创建结果不重复创建；恢复先结算已接受事件 |
| 账号或任务串线 | 将账号、工作区、模型与首条实际任务绑定；子任务身份隔离 | 错账号、回退与分支拒绝，子任务身份回归通过 |
| 精简模式限制工具与提示词 | 新增独立 full 入口；保留旧入口 | 官方 CLI 无 bare/替换提示词，原生 Skill 和文件工具实际成功 |
| 隔离目录缺少用户 Skills | 继承用户发现目录及普通设置，独立路由与会话状态 | 用户原件保留；原生 Skill 发现与调用分别检查 |
| 动态 MCP schema 超大 | 原生 schemas 原样；MCP 目录发现与精确 schema 按需提供 | 全工具可发现、schema 完整、本机 MCP 实际执行且有独立证明 |
| 安装只适合当前机器 | 累积补丁、旧版升级补丁、相对路径入口 | 干净固定源码安装、旧版升级、重复安装与进程清理检查 |
